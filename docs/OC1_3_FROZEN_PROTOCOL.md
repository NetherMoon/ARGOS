# OC1.3 cold-start timing protocol

The two timing runs use the same frozen OC1.1 scientific search rules: W2-short-qos5_4.5_4_3.5, N=1000, U=0.6; the same ten frozen arrival identities and fixed search runtime seed; p90 <= 0.30, every Pj <= 0.10, valid evidence; eight of ten passes required on a **complete** panel; and minimum mean canonical objective across all ten among eligible bids. The 15-point V3/independent initial screen, g8 ranking, legal structured proposal pack, two measured anchors, two-of-eight independent refinement quota, and third-failure early rejection are unchanged from the frozen post-development protocol. Neither the OC1.2 winner nor any measured simulator results are imported.

OC1.3 changes only how predeclared candidate/table tasks fill workers. A deterministic scheduler favors the least-measured active bids and may place up to four pending arrival tables for one bid in a single wave when workers would otherwise be idle. Each wave is frozen before dispatch, at most ten workers run concurrently, all launched results are retained, and no new tasks are launched after three **observed** failures. A wave already in flight may finish after a third failure; this possible extra work is part of the declared scheduler. Worker completion order cannot change the next wave or proposal batch. The same scheduler is used for both cold runs.

The first run has a 1200-second soft **search** target and a 400-new-call hard cap. The second has a 600-second soft search target and a 300-new-call hard cap. A launched wave may finish slightly after the soft target. Each run has a new output directory; the runner regenerates and verifies immutable job tables and V3 candidate cloud, and executes every FlexDC candidate evaluation anew. It reuses the verified historical V3 bank, which is job-table independent; bank generation time and current cloud scoring time are reported separately. Neither cold run performs held-out assessment or feeds the OC1.2 assessment into search.
